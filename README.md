# 负资金费率"现货 + 永续"策略：可复现版

> 研究/回测代码，不是投资建议。数字都是历史模拟，不是实盘业绩。仓库不含密钥、持仓或库存数据。没有 LICENSE 文件（许可证未决定，默认保留所有权利）。
> 报告、图表和 PDF 不放在这里，内部另发。

## 1. 策略规则（头条口径）
- **本金**：1000 万 USDT（10M）。
- **做什么**：某币永续资金费率为负时，卖出自有现货（库存口径 A，只用已有库存借出的币），同时做多等量永续合约，收取空头付给多头的资金费。借币利息按假设为 0。
- **进场**：资金费率为负、期望收入（资金费 + 基差收敛）不低于预期进场成本的 2 倍时进场（`r7_lib.py` 的 `gate_r7`：`ei >= m * C`，`v13lib.run_fix` 默认 `m=2.0`）（`run_r7.py` 的 r7 闸门，冲击成本用过去数据校准）。
- **出场（0h）**：最近 24 小时累计资金费率转正时立即出场，不等确认（配置 `cons_c0`）。
- **仓位上限**：每币不超过执行团队给的上限（USDT 上限和币数量上限都要满足）；不超过该币未平仓量（OI）的 10%；每小时成交不超过该小时成交量的 3%（pov）。
- **成本模型（cons 保守口径）**：taker 手续费，现货 10bp、永续 5bp（无 BNB 折扣）；买卖价差和冲击成本按公开盘口/成交数据逐币逐小时校准；自身冲击 `k_imp=4`：我们每占某币 1% OI，资金费率被抬高 4 bp/8h（从未用实盘标定）；资金费按全额计入，包括自身冲击；残余成本放大 3 倍。
- **窗口**：样本内 IS 到 2026-06-30，留出期 HO 是 2026-07-01 到 2026-10-27，全年 FY 是 2025-10-28 到 2026-10-27。

## 2. 需要的输入
| 环境变量 | 内容 |
|---|---|
| `NFB_DATA` | 数据目录，必须包含 `ds/dataset.npz`、`ds/dataset_meta.csv`（逐小时数据集）和 `calib/ag.csv`、`calib/bd.csv`（冲击校准表） |
| `NFB_CAP_FILE` | 逐币上限 CSV，**由执行团队提供**，不在仓库。三列：`fut_symbol,cap_usdt,cap_qty_token`。格式见 `repro/cap_file_example.csv`（假数字） |
| `NFB_ROOT` | 输出根目录（可选，默认当前目录），结果写到 `$NFB_ROOT/out/` |

数据来源：全部是币安公开数据（data.binance.vision 的永续/现货 1h K 线、资金费率历史、OI 与 metrics；fapi 的 exchangeInfo）。冲击校准表用 `repro/calib/calib_dl.py bd|ag <币清单>` 从公开 bookDepth / aggTrades 生成。币清单就是上限文件里的 `fut_symbol`。原始数据下载并合并成 `dataset.npz` 的脚本还没有放进本仓库，目前由研究方直接提供构建好的 `NFB_DATA` 目录。

## 3. 复现命令
```
pip install numpy pandas numba
export NFB_DATA=<数据目录>
export NFB_CAP_FILE=<执行团队提供的上限 CSV>
export NFB_ROOT=<输出目录>
python3 repro/run_headline.py
```
预期输出（约 30 秒）：
```
IS: 年化 61.04%  笔数 1426  净利 411.4 万U
HO: 年化 30.35%  笔数 361  净利 98.9 万U
FY: 年化 51.07%  笔数 1776  净利 510.7 万U
```
如果用的上限文件不同，结果也会不同。

注：IS 1426 + HO 361 = 1787 笔，比 FY 的 1776 笔多 11 笔。原因是三个窗口各自独立运行：IS 运行在 6/30 末强制平掉所有仓位，HO 运行从 7/1 空仓重新开始；而 FY 是连续一次运行，有 33 笔交易跨过 6/30–7/1 边界。路径因此不同（HO 有 15 笔是 FY 里没有的，FY 有 4 笔不在 IS/HO 里），11 是净差，不是 11 笔被简单重复计数。


## 4. 代码结构
- `repro/run_headline.py`：唯一入口。
- `repro/lib/`：引擎和规则模块（`engine_v12s.py` 是带逐笔记账的引擎，`lib12s.py` 负责加载数据和仓位上限，`r9_run.py`/`r10_run.py` 定义口径 `cons_c0`，`run_r7.py`/`r7_lib.py` 负责成本校准和进场闸门，`v13lib.py` 是运行封装）。
- `repro/calib/calib_dl.py`：从币安公开 bookDepth / aggTrades 生成冲击校准表（独立脚本，复现头条不需要运行）。
